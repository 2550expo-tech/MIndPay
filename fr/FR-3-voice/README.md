# FR-3 Voice Entry · พูดจด

**ผู้รับผิดชอบ:**  Vorachone Srijariyakorn (stangmoonoi)
**ชุดงาน:** ชุดที่ 2


## FR นี้แก้ปัญหาอะไร

การจดเงินสดคือส่วนที่คนเลิกทำก่อน เพราะต้องกดหลายขั้น FR-4 ช่วยเรื่องเงินโอน (มีสลิป) แต่เงินสด เช่น ข้าวกลางวัน ค่าวิน ขนมหน้าโรงเรียน ไม่มีสลิป ถ้าต้องเปิดฟอร์ม พิมพ์เงิน พิมพ์ชื่อ เลือกหมวด แล้วกดบันทึกทีละรายการ หลายคนจะเลื่อนไปจดตอนเย็นแล้วก็ลืม FR-3 ทำให้ผู้ใช้ พูดประโยคเดียว จดได้หลายรายการ เช่น "ข้าว 50 น้ำ 15 ค่ารถ 25" ใช้แตะประมาณ 3 ครั้ง แทนฟอร์มที่ต้องแตะ 15 ครั้งขึ้นไป ถ้าเครื่องฟังเสียงไม่ได้ ก็พิมพ์แบบที่พูดได้ผลเหมือนกัน

## Requirement และเกณฑ์ผ่าน (Acceptance criteria)

Requirement: "ผู้ใช้พูดรายการ เช่น 'ข้าว 50 บาท' แล้วแอปบันทึกเป็นรายการให้"
1. พูด "ข้าว 50 บาท" แล้วได้ ข้าว ฿50 หมวดอาหาร และตัวเลขเป็นเลขหรือคำไทยก็ได้ ("ห้าสิบ", "ร้อยห้า" = 150, "สองพันห้า" = 2,500, "ร้อยครึ่ง") (TC-59, TC-61)
2. พูดหลายรายการในประโยคเดียวได้ "ได้เงินจากแม่ 500" เป็นรายรับ "เมื่อวาน" ลงวันที่เมื่อวาน และ "ข้าว 2 จาน 100" ไม่นับ 2 เป็นเงิน (TC-60)
3. เห็นรายการก่อนบันทึก สลับรายรับ/รายจ่ายหรือเอาออกได้ แล้วกดบันทึกครั้งเดียว ยอดเงินอัปเดตทันที (E2E)
4. ฟังภาษาไทย (th-TH) ด้วยตัวแปลงเสียงของมือถือหรือเบราว์เซอร์ เครื่องที่ฟังไม่ได้หรือแอปรุ่นเก่ายังพิมพ์แบบที่พูดได้ และไม่ crash (E2E ตัวฟังเสียงจำลอง, MT-12)
5. ขอสิทธิ์ไมโครโฟนเฉพาะตอนแตะไมค์ครั้งแรก เก็บเฉพาะรายการที่กดบันทึก ไม่เก็บเสียง (MT-12)
6. กรณีที่พบจากการตรวจ repo (TC-80): "ค่าไฟ 711" ไม่กลายเป็นเซเว่น, "2 พันห้า" = 2,500, "ร้อยหนึ่ง" = 101, พูดจำนวนก่อนชื่อได้, เงินเข้าที่จะเอาไปซื้อของยังเป็นรายรับ, แต่ละรายการได้วันของตัวเอง, บันทึกซ้ำหลังพลาดบางรายการไม่ซ้ำ

## ทำงานยังไง

1. แตะไมค์ ที่ voice.tsx (toggleListening) ขอสิทธิ์ไมโครโฟนครั้งแรก แล้วเรียก listen()
2. ฟังเสียง ที่ speech.ts (มือถือ) หรือ speech.web.ts (เว็บ) ฟัง th-TH และส่งข้อความกลับมาเรื่อย ๆ ระหว่างพูด
3. ใส่ข้อความลงช่อง (changeText) เป็นข้อความเดียวกับที่ผู้ใช้พิมพ์เองได้
4. เข้าใจประโยค ที่ voice.ts ฟังก์ชัน parseSpokenEntry ทำ 6 ขั้น

   4.1 ขั้น 1–3 ทำให้ข้อความเป็นมาตรฐาน: เลขไทย→อารบิก, ตัดคอมมา, ฿→บาท, ทำป้ายวัน, ตัดคำลงท้าย, แปลงเลขคำไทยเป็นเลข

   4.2 ขั้น 4 หาจำนวนเงินทุกตัว (เลขที่ตามด้วยหน่วย เช่น จาน แก้ว ไม่นับเป็นเงิน)

   4.3 ขั้น 5 แบ่งชื่อให้แต่ละจำนวนเงิน

   4.4 ขั้น 6 ตัดสินรายรับ/รายจ่าย ทำความสะอาดชื่อ เดาหมวด ใส่ dayOffset
5. ผู้ใช้ตรวจ ที่การ์ดรายการใน voice.tsx สลับรายรับ/รายจ่ายหรือเอาออก แล้วกด "บันทึก N รายการ"
6. บันทึก ผ่าน addTx ของ FR-1 เป็น "ยืนยันแล้ว" ยอดเงินบนหน้าหลักเปลี่ยนทันที
   
ข้อมูลเงินเก็บเป็นสตางค์ (จำนวนเต็ม) และใช้ dayOffset แทนวันที่ ทำให้ voice.ts เป็นฟังก์ชันล้วนที่ทดสอบง่าย เสียงไม่ถูกอัดและไม่ถูกส่งไปเซิร์ฟเวอร์ของเรา

## ข้อจำกัดและงานต่อไป

1. รายการที่ไม่มีราคาถูกข้ามเงียบ ๆ (เสี่ยงข้อมูลหาย): "ข้าว 50 น้ำ 15 ขนม" ขนมหายไปโดยไม่แจ้ง → งานต่อ: แสดงคำเตือน "ขนม ยังไม่มีราคา" ในหน้าตรวจรายการ
2. คำบอกวันที่ใช้ได้เฉพาะพูดครั้งเดียวท้ายประโยค (เสี่ยงลงวันผิด): "ค่าหอ 3500 เมื่อวาน ข้าว 60 วันนี้" ได้เมื่อวานทั้งสองรายการ → งานต่อ: จับคู่คำบอกวันกับรายการก่อนหน้า
3. เงินคืนที่ไม่มีคำรายรับถูกนับเป็นรายจ่าย (ยอดคงเหลือเพี้ยน): "เพื่อนโอนค่าข้าวคืน 50" ได้ −฿50 → งานต่อ: ใช้คำ "คืน" ท้ายประโยคเป็นสัญญาณรายรับ (ต้องระวัง "ซื้อของคืน")
4. หน่วยที่มีคำต่อท้ายถูกอ่านเป็นจำนวนเงิน (ยอดเกิน): "ตั๋วหนัง 2 ที่นั่ง 360" ได้ [ตั๋วหนัง ฿2] [ที่นั่ง ฿360] → งานต่อ: เพิ่มคำหน่วยยาว
5. ใช้กฎจับคำ ไม่เข้าใจประโยคอิสระ และพึ่งความแม่นของตัวแปลงเสียงในเครื่อง: ประโยคยาวหรือพูดอ้อมอาจแยกผิด → งานต่อ: ใช้ AI ช่วยเฉพาะประโยคที่กฎเข้าใจไม่ได้ โดยคงการให้ผู้ใช้ตรวจก่อนบันทึก
